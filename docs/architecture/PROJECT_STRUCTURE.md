# Project Structure

Principle: the smallest structure that builds with standard Flutter tooling and enforces the architecture boundaries. Directories that do not exist yet are marked *(planned)* and are created only by the milestone that needs them. Empty placeholder directories are forbidden.

## 2. What differs from the original proposal, and why

| Proposed | Decision | Reason |
|---|---|---|
| `lib/data`, `lib/domain`, `lib/services` top-level | Per-feature `data/domain/presentation`; shared DB in `core/database` | Feature-first keeps changes local; avoids god-folders |
| `engines/camera-engine`, `vision-engine`, `cartoon-engine`, `recording-engine` as separate directories | Packages inside one Android library module `camanime_engine` | Same boundaries (enforced by packages and review) without four Gradle modules, build-time cost, or cross-module API churn; can be split later if justified |
| `engines/animation-engine` | Not created | Mode B is v2.0 |
| Root `assets/` | `apps/mobile/assets` (Flutter) and engine `src/main/assets` (native) | Assets must live where the build tool packages them |
| Root `CHANGELOG.md`, root `analysis_options.yaml` | `docs/project/CHANGELOG.md`; `analysis_options.yaml` inside `apps/mobile` | One changelog; analyzer config belongs to the Dart package |
| `research/segmentation`, `stylization`, `tracking`, `benchmarks` | Per-spike directories on demand | Avoid empty directories |

## 3. Directory kinds

| Path | Kind |
|---|---|
| `apps/mobile` | Flutter application (single Dart package). Only Dart package in the repo |
| `apps/mobile/android` | Gradle multi-module project (Android) |
| `apps/mobile/android/app` | Android application module (Flutter host) |
| `apps/mobile/android/camanime_engine` | Android **library** module with Kotlin source sets `main`, `test`, `androidTest`; consumed by `:app` |
| `engines/native-core` *(planned)* | Independent C++ static library built by CMake, linked into the engine via `externalNativeBuild`; platform-neutral |
| `docs`, `scripts`, `research` | Non-build content |

## 4. Naming conventions

- Dart: files `snake_case.dart`; classes `UpperCamelCase`; providers `somethingProvider`; one public type per file when practical; tests `<name>_test.dart`.
- Kotlin: package `com.camanime.engine.<area>`; classes `UpperCamelCase`; files named after the main class; interfaces without `I` prefix; tests `<Class>Test.kt`.
- GLSL: `<purpose>.vert` / `<purpose>.frag` in `assets/shaders/`; style params `assets/styles/<style_id>.json`.
- Style IDs: `snake_case` (`cel_pop`, `ink_comic`, `soft_pastel`, `noir_sketch`, `original`). Mode IDs: `mode_a_stylize`, `mode_b_character` (future).
- Bridge names: `domain.action` (`camera.start`) in lower camelCase after the dot; error codes `UPPER_SNAKE_CASE`.
- Docs: `UPPER_SNAKE_CASE.md` under `docs/<area>/`.

## 5. File ownership (who may change what)

| Area | Owner role | Change rule |
|---|---|---|
| `docs/integrations/API.md` + both bridge sides | Bridge owner | Change all three in one commit |
| `assets/shaders/*`, `styles/*` | Rendering owner | Needs updated golden/visual check |
| `assets/models/*` + `manifest.json` | Model owner | Needs catalog + license entry and new checksum |
| `core/database/*` | Data owner | Schema change = migration + test |
| `AGENTS.md`, `docs/architecture/TECHNICAL_DECISIONS.md` | Project owner | Only with explicit approval |

With one developer the roles collapse into the project owner; the table still tells an AI agent which documents to update.

## 6. Where new code goes

| New thing | Place |
|---|---|
| A screen | `features/<feature>/presentation/` + route in `app/router.dart` + [SCREEN_SPECIFICATIONS](../design/SCREEN_SPECIFICATIONS.md) entry |
| A cartoon style | `assets/styles/<id>.json` (+ shader only if it needs a new pass) + `features/styles` catalog entry |
| A new engine command | `API.md`, `bridge/`, Dart client, tests, in one change |
| A new DB table/column | `core/database/` table + migration + `DATABASE.md` |
| A new ML model | `assets/models/` + `manifest.json` + `MODEL_CATALOG.md` + license notice |
| A shader pass | `gl/` pass class + `assets/shaders/` + `RENDERING_ENGINE.md` |
| A setting | Settings repository + `DATABASE.md` keys table + `FEATURE_SPECIFICATIONS.md` F-08 |
| Shared Dart utility | `core/` (only if used by ≥ 2 features) |

## 7. Required for MVP vs future

| Required for MVP | Future |
|---|---|
| `apps/mobile` incl. `camanime_engine`, `docs`, `scripts` | `engines/native-core`, `ios` implementation, animation/rigging code, character assets |
